# 全维度项目深度审计执行计划

## 0. 启动门槛

- [x] 用户评审并批准 `prd.md`、`design.md`、`implement.md`。
- [x] 运行 `task.py start` 后再进入审计执行；启动不授权产品代码修改。
- [x] 保存当前 `git status --short --branch`，确认 `.codex/config.toml` 为任务前已有改动。

## 1. 建立仓库事实地图

- [x] 枚举文件并排除依赖、构建产物和秘密文件；统计语言、目录、文件/函数规模和生成物。
- [x] 读取根入口、package/Cargo metadata、Tauri capabilities、构建/发布/CI 配置和 Trellis 三层规范。
- [x] 从运行入口追踪承重主路径，画出 Module、Interface、Seam、Adapter、持久化和事件流地图。
- [x] 枚举公共 Surface：Tauri commands/events、配置、schema、导出、错误与跨层 DTO，并定位消费者。
- [x] 读取相关历史提交、既有审计/修复任务和 CHANGELOG，用当前代码验证历史声明。

## 2. 完成痛点与产品证据

- [x] 复核 `research/user-pain-points.md` 的一手来源、链接、措辞与来源—推断分离。
- [x] 将痛点映射到当前功能、缺口、非目标和低复杂度机会；不把 20-20-20 或 Eye-Care Index 写成医学疗效。
- [x] 确认研究建议没有制造与核心主路径平行的产品或配置体系。

## 3. 执行静态与结构审计

- [x] 搜索 `TODO/FIXME/XXX`、lint/coverage 抑制、unchecked cast、跳过/隔离测试、空 catch/静默错误和默认值兜底。
- [x] 查找重复默认值、事件/枚举/schema/统计口径、手改派生产物、横向导入和循环依赖。
- [x] 检查单文件 >500 行、函数 >80 行；只有能命名两个独立责任时才建议拆分。
- [x] 对主要 Module 执行 Interface 深度、删除测试、依赖分类和测试面检查。
- [x] 检查外部输入只在 seam 处验证一次；内部不重复解包、类型防御或 `?? default`。
- [x] 审计配置/数据库写入的一致性、事务、幂等和失败语义；审计异步事件的乱序、重复和竞争。
- [x] 审计 capability/权限、IPC 暴露、日志/统计隐私、路径/进程名等潜在敏感信息。

## 4. 执行 UI/UX 与运行链审计

- [x] 通过源码、测试和可用的静态/运行证据逐一走查首次启动至退出/重启的任务流。
- [x] 核查预警、提醒、开始/跳过、暂停/恢复和智能跳过的可解释性及状态一致性。
- [x] 核查托盘、多屏、热键、主题/语言、键盘焦点、缩放、对比度、动效和屏幕阅读器支持。
- [x] 核查错误、空、离线/权限拒绝、平台能力缺失、休眠/唤醒和时钟变化状态。
- [x] 如需启动 GUI 或长期运行进程，先单独获得用户授权；否则将动态 UX 项标为未验证。

## 5. 运行项目检查

先读取 lockfile、`package.json`、Cargo/CI 配置确定准确命令；不得安装/升级依赖或改 lockfile。候选检查如下，实际报告以项目声明为准：

- [x] 前端格式：`npm run format:check`。
- [x] 前端静态检查/typecheck：`npm run check`。
- [x] 前端测试与覆盖率：`npm run test:coverage` 或项目 CI 的等价命令。
- [x] 前端生产构建：`npm run build`。
- [x] Rust 格式、lint、测试与覆盖率门槛：运行 CI 文件声明的准确命令。
- [x] 项目聚合 CI/smoke：运行 `npm run ci` 或仓库等价命令，避免与上述检查无意义重复。
- [x] 对“守卫可失败”只做安全、可回滚且不污染工作树的验证；无法种植违规时检查守卫实现和历史失败证据并降低置信度。
- [x] 检查后复核 Git 状态，确认只有任务审计文档和用户原有 `.codex/config.toml` 发生变化。

## 6. 建立排熵快照

- [x] 记录九类 Keel rot indicator 的可复现口径和当前值。
- [x] 用 Git 历史检查近几个发布周期的 Surface、概念、抑制项、旁路和文档所有权变化；口径不一致则只保留基线。
- [x] 识别一个最小 subtraction batch，包含 owner、删除目标、完成条件和下一次快照时间；不新建治理平台。

## 7. 汇总报告与路线图

- [x] 按九维模型评分并给出 A/B/C 证据置信度；交叉问题只在一个主维度扣分。
- [x] 逐条登记发现，P0/P1 必须具有直接证据、根因链、最小修复切片和可失败验收。
- [x] 将建议分成立即止损、短期深化、长期治理，标注收益、成本、依赖、owner、回滚/删除条件。
- [x] 输出低复杂度体验创新，每项说明痛点、主路径接入点、Surface 成本和明确非目标。
- [x] 单列发布门禁和未验证项，不将单平台/静态证据外推为跨平台通过。

## 8. 交付前复核

- [x] 检查每个评分结论均能追溯到事实证据，推断和未知有显式标签。
- [x] 检查建议未用 silent fallback、兼容残留、flag 分支、投机 seam 或整库重写掩盖根因。
- [x] 检查研究引用为一手来源且链接可访问；非一手材料不承担关键主张。
- [x] 检查主报告没有复制形成第二套规范，而是引用权威来源。
- [x] 运行 Markdown/链接/项目既有文档检查（如有），并报告所有未运行、失败或环境阻塞项。
- [x] 向用户交付报告路径、总分与置信度、P0/P1 摘要、验证结果和下一最小行动；不实施修复。

## 风险文件与停止条件

- `.codex/config.toml`：用户已有改动，只观察状态，不读取其潜在凭据字段、不编辑。
- `src-tauri/migrations/`、capabilities、签名/发布配置：只读；发现问题只报告。
- 若检查会写数据库、用户配置、系统自启动、通知权限或平台密钥，停止并请求授权。
- 若发现秘密、PII 或可利用安全问题，不在公开报告中输出具体秘密或武器化步骤，改为脱敏位置和修复条件。
