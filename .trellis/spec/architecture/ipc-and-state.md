# IPC 接口与状态机

> Eyezen 跨边界契约：Commands 表、Events 表、错误类型、IPC 边界规则、Timer 状态机。
> 关键词约定：**MUST** = 强制，**SHOULD** = 推荐，**MAY** = 可选。

---

## Commands（Frontend → Backend）

实际注册见 `src-tauri/src/commands/mod.rs` 与 `src-tauri/permissions/autogenerated/`；前端封装在 `src/lib/commands.ts`。

| Command | 参数 | 返回 | 允许窗口 | 说明 |
|---------|------|------|---------|------|
| `get_state_snapshot` | -- | `StatePayload` | main / tip / tray | 拉取当前状态快照 |
| `start_rest` | -- | `()` | tip / tray | 进入 Resting |
| `skip_rest` | -- | `()` | tip / tray | 跳过当前提醒回到 Working |
| `pause_timer` | -- | `()` | main / tray | 暂停（保存 `prev_state` + `remaining`）|
| `resume_timer` | -- | `()` | main / tray | 恢复到暂停前状态 |
| `get_config` | -- | `Config` | main | 读取完整配置（同步 `current()`，无 I/O）|
| `update_timer_config` | `TimerConfig` | `()` | main | 校验后通过 `spawn_blocking` 写 TOML |
| `update_behavior_config` | `BehaviorConfig` | `()` | main | 同上，纯 bool 字段不需范围校验 |
| `update_display_config` | `DisplayConfig` | `()` | main | 校验 `language`/`theme` 枚举值 |
| `get_daily_stats` | `{ range }` | `Vec<DailyStat>` | main | **P2**（未实现）|

新增 command MUST 同步更新：`commands/mod.rs` 注册 + `permissions/autogenerated/<name>.toml` + 对应 `capabilities/*.json` allow 列表 + `src/lib/commands.ts` 封装。完整清单见 [`change-management.md`](./change-management.md)。

## Events（Backend → Frontend）

实际常量见 `src-tauri/src/events/mod.rs`；前端封装在 `src/lib/events.ts`。

| Event | Payload | 触发方 | 说明 |
|-------|---------|--------|------|
| `state_changed` | `StatePayload` | `TimerService` 的 `EmitStateChanged` effect | 状态变更通知，UI 同步唯一来源 |
| `config_changed` | `Config` | `ConfigService` 写入成功后 | 配置变更，前端 store 据此更新 |
| `navigate_tab` | `string` | 前端发起（tray-panel → main）| 前端自洽事件，**不**经 Rust 处理 |

前端 capability allow 列表中 MUST 显式列出每个 event 名（见 `src-tauri/capabilities/main-window.json`），通配监听被 Tauri v2 拒绝。

## 错误类型

后端唯一错误类型，定义见 `src-tauri/src/error.rs`：

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(tag = "kind", content = "detail")]
pub enum AppError {
    ConfigInvalid { field: String, reason: String },
    InvalidOperation { operation: String, reason: String },
    IoError { message: String },
}
```

- Command 返回值 MUST 是 `Result<T, AppError>`，由 Tauri 自动序列化为前端可捕获的 reject。
- `From<std::io::Error>` 与 `From<toml::de::Error>` 已实现，业务代码 SHOULD 用 `?` 传播。
- 前端在 `invoke().catch(e)` 中 MUST 把 `e.kind` 当判别字段使用，MUST NOT 解析 message 字符串做分支。
- 新增 variant MUST 同步：`error.rs` + 涉及 command 的测试 + 前端错误处理分支。

## 通信模式

```
初始化: listen('state_changed') / listen('config_changed') 先注册
        → invoke('get_state_snapshot') / invoke('get_config') 拉取初始状态
运行时: 后端推 state_changed / config_changed，前端 store 据此覆写
操作:   invoke('start_rest') / invoke('update_timer_config', { config })
```

- 前端 MUST 先注册 listener 再发起 invoke，避免初始事件丢失。
- 前端 MUST NOT 自行缓存或乐观更新可由后端推送的字段；详见 [`../frontend/state-management.md`](../frontend/state-management.md)。
- 后端 MUST NOT 期待前端轮询，状态变更全部通过 push。

## IPC 边界规则

### 输入校验

- Command 层 MUST 在参数转交服务前做范围校验（实际示例：`validate_timer_config` / `validate_display_config` in `src-tauri/src/commands/mod.rs`）。
- Service 层 MUST 假设上游已校验，但 MUST 对内部不变量做 debug_assert。
- 前端传入的数据 MUST 视为不可信，禁止把字符串直接拼到文件路径或 SQL。
- 校验失败 MUST 返回 `AppError::ConfigInvalid { field, reason }`，前端据此高亮表单字段。

当前实际范围（见 `commands/mod.rs`）：

| 字段 | 范围 |
|------|------|
| `work_minutes` | 1 – 120 |
| `rest_seconds` | 5 – 300 |
| `pre_alert_seconds` | 5 – 60 |
| `alert_timeout_seconds` | 10 – 300 |
| `language` | `zh-CN` / `en` / `en-US` |
| `theme` | `light` / `dark` |

修改范围 MUST 同步更新前端 Stepper 的 `min` / `max`。

### 超时策略

- Command 执行 SHOULD 在 5 秒内完成；前端 `invokeWithTimeout` 已硬编码 5000ms（见 `src/lib/commands.ts`）。
- 涉及磁盘 I/O 的 command（`update_*_config`）MUST 使用 `tokio::task::spawn_blocking` 包裹，避免阻塞 Tauri runtime（实际见 `commands/mod.rs:107`）。
- 前端超时后 MUST 给用户可见反馈（toast / 表单 inline 错误），MUST NOT 静默丢弃。

### 错误返回

- Command MUST 返回 `Result<T, AppError>`。
- Command MUST NOT `unwrap()` 或 `panic!()`；服务内部不可恢复错误 SHOULD 通过 `tracing::error!` 记录并返回 `AppError::IoError`。
- 错误 `reason` MUST 对用户友好，技术细节（stack trace、内部状态）记入日志。

## Timer 状态机

实现在 `src-tauri/src/services/timer/{state.rs,machine.rs,effect.rs,service.rs}`。状态机是**纯函数核心**，副作用通过 `Effect` 在锁外执行。

### 状态

定义见 `src-tauri/src/services/timer/state.rs`：

| 状态 | 含义 | 阶段 |
|------|------|------|
| `Working` | 工作计时中（含 PreAlert 之前）| MVP |
| `PreAlert` | 预提醒：托盘 tooltip 变化 + 可选音效 | MVP |
| `Alerting` | 全屏提醒显示，等待用户操作（超时自动消失）| MVP |
| `Resting` | 用户选择休息，倒计时中 | MVP |
| `Paused` | 用户手动暂停，携带 `paused_from` + `paused_remaining` | MVP |
| `Away` | 离席检测触发 | P2（未实现）|

- `Paused` 数据 MUST 通过 `Inner.paused_from: Option<TimerState>` + `Inner.paused_remaining: Option<Duration>` 承载，MUST NOT 用全局可变状态。
- 恢复时 MUST 通过 `apply_transition` 回到 `paused_from` 并按 `paused_remaining` 重算 `state_entered_at`，MUST NOT 总是跳回 `Working`。
- `TimerState::as_str()` 返回的 `snake_case` MUST 与前端 `StatePayload.state` 字段值保持一致（实际见 `state.rs:21`）。

### 状态转换

```
start --> Working
Working  --tick (elapsed >= work - pre_alert)--> PreAlert
PreAlert --tick (elapsed >= pre_alert)--> Alerting
Alerting --user:start_rest--> Resting
Alerting --user:skip--> Working
Alerting --tick (elapsed >= alert_timeout)--> Working    // 自动消失，计为 skip
Resting  --tick (elapsed >= rest)--> Working
Any(except Paused) --user:pause--> Paused                // 保存 prev_state + remaining
Paused   --user:resume--> prev_state                     // 按 remaining 续跑
Working  --detector:away--> Away                         // P2
Away     --detector:back--> Working                      // P2
```

- 状态转换 MUST 通过 `resolve_user_event()` / `step_time()` 纯函数返回的 `Transition` 触发，MUST NOT 在业务代码中直接 mutate `Inner.state`。
- 非法转换（例如在 `Working` 收到 `Resume`）MUST 返回 `None`，由 `TimerService` 转换为 `AppError::InvalidOperation`，MUST NOT panic。
- `SkipFlags::any_active() == true` 时，`Working` 超时 MUST 重置工作计时器（`Effect::ResetWorkTimer`），MUST NOT 进入 `PreAlert`。

### 核心三函数

```rust
// 纯函数：用户事件 → 状态转换
pub(crate) fn resolve_user_event(state: &TimerState, event: UserEvent) -> Option<Transition>;

// 纯函数：时间推进 → 状态转换
pub(crate) fn step_time(inner: &Inner, now: Instant, skip_flags: &SkipFlags) -> Option<Transition>;

// 锁内收集副作用（实际实现：collect_effects + collect_tick_effects）
pub(crate) fn collect_effects(transition: &Transition, inner: &Inner) -> Vec<Effect>;
```

- `resolve_user_event` 与 `step_time` MUST 是纯函数：无 I/O、无 logging、无 `Instant::now()` 之外的副作用。
- `collect_effects` MUST 在持锁状态下调用并立即返回 `Vec<Effect>`；持锁 MUST NOT 跨 `await`。
- 返回的 `Vec<Effect>` MUST 在**锁外**执行，避免回调时反向持锁导致死锁。

### Effect 类型

定义见 `src-tauri/src/services/timer/effect.rs`：

```rust
pub(crate) enum Effect {
    EmitStateChanged(StatePayload),
    ShowTipWindows,
    HideTipWindows,
    PlaySound(SoundType),
    UpdateTray(TrayUpdate),
    ResetWorkTimer(Duration),
}
```

- Effect MUST NOT 持有锁引用或可变 service 引用；通过克隆值传递。
- Effect 执行失败 MUST 记录 `tracing::warn!` 但 MUST NOT 反向抛回状态机，MUST NOT 阻塞下一次 tick。
- `EmitStateChanged` 是前端同步唯一来源；新增状态字段 MUST 同步更新 `StatePayload`（见 `src-tauri/src/models/types.rs`）+ ts-rs 绑定。
- `RecordStat` 等 P2 effect 加入时 MUST 同步更新本表。

### SkipFlags

```rust
pub(crate) struct SkipFlags {
    pub(crate) fullscreen_active: bool,
    // P2: whitelisted_process / user_away / outside_workday
}
```

- `SkipFlags::any_active() == true` 时，`Working` 超时仅触发 `Effect::ResetWorkTimer(work_duration)`，状态保持 `Working`。
- 添加新 flag MUST 同时扩展 `any_active()`、`step_time` 中的处理，以及对应配置（如 `BehaviorConfig::fullscreen_skip`）。
