### Scenario: Statistics Trend IPC

#### 1. Scope / Trigger

- Trigger: 统计页跨 SQLite 存储、Rust service、Tauri command、ts-rs binding、Svelte/ECharts UI。
- Applies when adding or changing rest statistics persistence, aggregation buckets, or the Statistics page command payload.

#### 2. Signatures

- Backend command: `get_statistics_trends(timezone: Option<String>) -> Result<StatisticsTrendPayload, AppError>`
- Frontend wrapper: `getStatisticsTrends(timezone: string): Promise<StatisticsTrendPayload>`
- DTO source: `src-tauri/src/models/statistics.rs`; generated bindings: `src/lib/bindings/{StatBucket,StatisticsTrendPayload}.ts`
- DB writer effect: `Effect::RecordRestSession(RestSessionDraft)` emitted only for `Resting -> Working`.

#### 3. Contracts

- Request `timezone`: optional IANA timezone name; frontend SHOULD pass `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- Backend fallback: if no timezone is provided, resolve OS IANA timezone via `iana-time-zone`; fallback to `UTC` only if the OS lookup fails.
- Response `StatisticsTrendPayload`: `timezone`, `daily`, `weekly`, `monthly`, `total_sessions`, `total_rest_secs`.
- Bucket labels: daily `YYYY-MM-DD`, weekly `YYYY-Www` using local ISO week, monthly `YYYY-MM`.
- Bucket counts use completed rest sessions, not alert prompts or skipped rests.

#### 4. Validation & Error Matrix

| Condition | Error |
|---|---|
| Invalid IANA timezone | `AppError::ConfigInvalid { field: "timezone", ... }` |
| Statistics DB not initialized | `AppError::InvalidOperation { operation: "statistics database", ... }` |
| SQLite open/query failure | `AppError::IoError { message: "database error: ..." }` |
| Corrupt stored timestamp | `AppError::IoError { message: "invalid stored statistics timestamp: ..." }` |

#### 5. Good/Base/Bad Cases

- Good: five completed `Resting -> Working` sessions in one local day return one daily bucket with `rest_sessions = 5`.
- Base: no rows returns empty `daily` / `weekly` / `monthly` and zero totals.
- Bad: timezone `"Not/AZone"` rejects before querying, so UI can show a load error.

#### 6. Tests Required

- Rust: DB auto-create/schema presence, persistence across service restart, five-session aggregation, timezone day boundary, month-end, DST fallback.
- Frontend: mock `commands.ts` IPC wrapper and assert Statistics page renders totals and switches day/week/month chart data.
- CI: `npm run ci` MUST pass after bindings are regenerated by `cargo test`.

#### 7. Wrong vs Correct

#### Wrong

```ts
import { invoke } from '@tauri-apps/api/core';
await invoke('get_statistics_trends');
```

#### Correct

```ts
import { getStatisticsTrends } from '$lib/commands';
await getStatisticsTrends(Intl.DateTimeFormat().resolvedOptions().timeZone);
```

## Scenario: AFK 跳过与检测能力

### 1. Scope / Trigger

- Trigger: AFK 跳过同时新增配置字段、平台能力、Tauri command、前端 Settings 控件和 Timer `SkipFlags`，属于跨层契约变更。
- Scope: 仅在 `Working` 到达工作阈值时抑制下一次提醒；不记录 AFK 段，不引入 `Away` 状态，不把平台能力写入 TOML。

### 2. Signatures

```rust
pub struct BehaviorConfig {
    pub afk_skip_enabled: bool,
    pub afk_threshold_minutes: u32,
}

pub struct DetectorCapabilities {
    pub afk_detection_supported: bool,
}

pub(crate) trait PlatformApi: Send + Sync {
    fn idle_duration(&self) -> Option<Duration>;
    fn supports_idle_detection(&self) -> bool;
}

#[tauri::command]
pub(crate) async fn get_detector_capabilities(
    services: State<'_, SharedAppServices>,
) -> Result<DetectorCapabilities, AppError>;
```

前端封装 MUST 保持一对一镜像：

```ts
export function getDetectorCapabilities(): Promise<DetectorCapabilities>;
export function updateBehaviorConfig(config: BehaviorConfig): Promise<void>;
```

### 3. Contracts

| 字段 / 返回值 | 类型 | 约束 |
|---------------|------|------|
| `behavior.afk_skip_enabled` | `bool` | 默认 `true`，由用户配置持久化 |
| `behavior.afk_threshold_minutes` | `u32` | 默认 `5`，有效范围 `1..=120` |
| `DetectorCapabilities.afk_detection_supported` | `bool` | 运行时平台能力，只读，不写入 TOML |
| `PlatformApi::idle_duration()` | `Option<Duration>` | `Some(duration)` 表示可判断 idle；`None` 表示不可用或降级 |
| `SkipFlags.afk_active` | `bool` | `afk_skip_enabled && idle_duration >= afk_threshold_minutes` |

`get_detector_capabilities` MUST 只读取 `DetectorService` 能力快照，不做磁盘 I/O。Settings MAY 用页面本地 `$state` 保存该快照用于灰显控件，但控件值仍 MUST 读取 `configStore.current.behavior`。

### 4. Validation & Error Matrix

| 条件 | 结果 |
|------|------|
| `afk_threshold_minutes == 0` | `AppError::ConfigInvalid { field: "afk_threshold_minutes", reason: "must be 1-120, got 0" }` |
| `afk_threshold_minutes > 120` | `AppError::ConfigInvalid { field: "afk_threshold_minutes", reason: "must be 1-120, got <value>" }` |
| `idle_duration() == None` | `afk_active = false`，不得误跳过提醒 |
| `supports_idle_detection() == false` | `get_detector_capabilities` 返回 `afk_detection_supported = false`，Settings 禁用 AFK 控件 |
| 平台 idle API 调用失败 | platform 层最多 `warn!` 一次并返回 `None`，错误不得穿透到 command/service |

### 5. Good/Base/Bad Cases

- Good: `afk_skip_enabled=true` 且 idle 时长等于或超过阈值时，`Working -> Working`，触发 `ResetWorkTimer` 并记录 `info!("skip: afk")`。
- Base: idle 时长低于阈值时，保留原行为进入 `PreAlert`。
- Bad: Wayland 或 idle API 不可用时，不跳过提醒，Settings 灰显 AFK 控件且不刷重复 warning。

### 6. Tests Required

- Config: `partial_toml_uses_defaults` 覆盖旧 TOML 缺少 AFK 字段时使用默认值。
- Command validation: `update_behavior_config` 覆盖 `afk_threshold_minutes` 的 `0` 和 `>120` 失败路径。
- Detector: 覆盖 idle 低于、等于、高于阈值，以及 `None` 不触发 AFK。
- Timer state machine: 覆盖 `SkipFlags::any_active()` 包含 `afk_active`，以及 `Working` 超时时 AFK 触发 `Working -> Working`。
- DTO/bindings: `DetectorCapabilities` JSON roundtrip + ts-rs binding 由 `cargo test` 生成。
- Frontend: Settings 覆盖能力不可用时控件禁用，以及阈值变更调用 `updateBehaviorConfig` 的完整子配置。

### 7. Wrong vs Correct

#### Wrong

```rust
// 不要为当前 AFK skip 增加状态语义；Away 保留给未来统计/长离席。
TimerState::Away
```

```ts
// 不要在 command 成功返回前乐观修改配置镜像。
configStore.current.behavior.afk_threshold_minutes = value;
```

#### Correct

```rust
SkipFlags {
    afk_active: behavior.afk_skip_enabled
        && detector.is_afk_for_threshold(behavior.afk_threshold_minutes),
    ..SkipFlags::default()
}
```

```ts
const updated: BehaviorConfig = { ...cfg.behavior, afk_threshold_minutes: value };
updateBehaviorConfig(updated).catch((err) => console.error(err));
```

## 错误类型

后端唯一错误类型，定义见 `src-tauri/src/error.rs`：

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(tag = "kind", content = "detail")]
pub enum AppError {
    ConfigInvalid { field: String, reason: String },
    InvalidOperation { operation: String, reason: String },
    IoError { message: String },
}
```

- Command 返回值 MUST 是 `Result<T, AppError>`，由 Tauri 自动序列化为前端可捕获的 reject。
- `From<std::io::Error>` 与 `From<toml::de::Error>` 已实现，业务代码 SHOULD 用 `?` 传播。
- 前端在 `invoke().catch(e)` 中 MUST 把 `e.kind` 当判别字段使用，MUST NOT 解析 message 字符串做分支。
- 新增 variant MUST 同步：`error.rs` + 涉及 command 的测试 + 前端错误处理分支。

## 通信模式

```
初始化: listen('state_changed') / listen('config_changed') 先注册
        → invoke('get_state_snapshot') / invoke('get_config') 拉取初始状态
运行时: 后端推 state_changed / config_changed，前端 store 据此覆写
操作:   invoke('start_rest') / invoke('update_timer_config', { config })
```

- 前端 MUST 先注册 listener 再发起 invoke，避免初始事件丢失。
- 前端 MUST NOT 自行缓存或乐观更新可由后端推送的字段；详见 [`../frontend/state-management.md`](../frontend/state-management.md)。
- 后端 MUST NOT 期待前端轮询，状态变更全部通过 push。

## Scenario: Global Hotkey Contracts

### 1. Scope / Trigger

- Trigger: 新增跨层快捷键配置、状态 command/event、后端系统插件集成。
- Scope: `HotkeysConfig` TOML schema、`HotkeyStatus` IPC payload、Settings 即时保存、后端 `HotkeyService` per-action best-effort 注册。

### 2. Signatures

- `get_hotkey_status() -> Result<HotkeyStatus, AppError>`
- `update_hotkeys_config(config: HotkeysConfig) -> Result<(), AppError>`
- Event: `hotkey_status_changed: HotkeyStatus`
- Timer dispatch:
  - `HotkeyAction::StartRest` → `TimerService::handle_user_event(UserEvent::StartRest)`
  - `HotkeyAction::SkipRest` → `TimerService::handle_user_event(UserEvent::Skip)`
  - `HotkeyAction::TogglePause` → `TimerService::toggle_pause()`

### 3. Contracts

- `HotkeysConfig` fields:
  - `start_rest: String`
  - `skip_rest: String`
  - `toggle_pause: String`
- Default TOML values MUST be non-empty and parseable by `tauri-plugin-global-shortcut`.
- `HotkeyStatus` fields:
  - `bindings: Vec<HotkeyBindingStatus>`
  - `macos_accessibility: "not_required" | "granted" | "missing"`
  - `last_error: Option<String>`
- `HotkeyBindingStatus.state` MUST be one of `registered`, `conflict`, `permission_missing`.
- Frontend MUST treat `HotkeyStatus` as backend truth for binding state; `Config.hotkeys` is only the requested persisted configuration.

### 4. Validation & Error Matrix

| Condition | Backend behavior | Frontend behavior |
|-----------|------------------|-------------------|
| Empty shortcut | `AppError::ConfigInvalid { field: "hotkeys.<field>" }` | Reset input to current config, show inline error |
| Unparseable shortcut | `AppError::ConfigInvalid` | Show error, keep old config visible |
| Duplicate shortcut IDs (within desired config) | `AppError::ConfigInvalid`; reject before any registry call so all previous bindings stay intact | Show conflict, do not persist |
| OS/plugin registration failure on a single action | Mark that action `conflict` with the registry message, best-effort restore its previous shortcut, other actions stay `registered`; `last_error` stays `None`; return `Ok` so TOML still persists | Inline `conflict` on that row only; top banner stays hidden |
| All desired actions fail to register | Every action ends `conflict`; `last_error` set to aggregated message; TOML still persists; `apply_config` itself returns `Err` so the caller (Settings) gets a global error | Every row shows `conflict`; top "快捷键未生效" banner reappears |
| Config save fails after successful registration | Re-apply previous bindings best-effort, return I/O/config error | Show error; config store remains old |
| macOS Accessibility missing | Whole-service skip (no per-action register), publish `permission_missing` status, set `last_error` accordingly | Show Settings guidance to authorize |

### 5. Good/Base/Bad Cases

- Good: User changes `toggle_pause` to a free shortcut → only that row re-registers; the other rows keep their already-registered bindings without churn; TOML is saved; `hotkey_status_changed` reports `registered` for all three.
- Base: Old TOML lacks `[hotkeys]` → serde defaults fill all three shortcut fields and startup per-action registration applies them independently.
- Bad (partial conflict): Another app owns one default shortcut → only that action becomes `conflict`; the other two stay `registered` and actually fire; `last_error` stays `None` so the top banner does NOT show. `last_error` only fires when (a) macOS Accessibility is `missing` or (b) every action failed.

### 6. Tests Required

- `Config::default()` includes hotkey defaults.
- `partial_toml_uses_defaults` proves old TOML without `[hotkeys]` still loads.
- `HotkeyAction` serializes/deserializes as stable `snake_case`.
- `HotkeyService` per-action semantics: `registration_failure_keeps_other_actions_active` (a single failure does not undo other actions), `partial_conflict_keeps_other_actions_registered_with_no_global_error` (mixed state ⇒ `last_error == None`), `all_bindings_failed_sets_last_error_and_returns_err` (all-fail path sets `last_error` and returns `Err`), `editing_conflict_to_free_shortcut_only_changes_target_row` (recovering one `conflict` row leaves the other rows' active bindings untouched).
- Timer tests prove manual `StartRest` works from `Working` / `PreAlert`, and toggle pause resumes from paused state.

### 7. Wrong vs Correct

#### Wrong

```rust
// Saves config first. If apply_config rejects the desired config
// (duplicate-within-config or all-fail), persisted config says one
// thing while the OS bindings say another.
services.config.update_hotkeys(config)?;
services.hotkeys.apply_config(&config)?;
```

#### Correct

```rust
// Apply hotkeys first (per-action best-effort: mixed registered/conflict
// is still Ok; only duplicate-config / all-fail / permission-missing
// produce Err). Persist TOML only after apply_config succeeds; on later
// persistence failure, re-apply the previous config best-effort.
services.hotkeys.apply_config(&config)?;
services.config.update_hotkeys(config)?;
```

## IPC 边界规则

### 输入校验

- Command 层 MUST 在参数转交服务前做范围校验（实际示例：`validate_timer_config` / `validate_display_config` in `src-tauri/src/commands/mod.rs`）。
- Service 层 MUST 假设上游已校验，但 MUST 对内部不变量做 debug_assert。
- 前端传入的数据 MUST 视为不可信，禁止把字符串直接拼到文件路径或 SQL。
- 校验失败 MUST 返回 `AppError::ConfigInvalid { field, reason }`，前端据此高亮表单字段。

当前实际范围（见 `commands/mod.rs`）：

| 字段 | 范围 |
|------|------|
| `work_minutes` | 1 – 120 |
| `rest_seconds` | 5 – 300 |
| `pre_alert_seconds` | 5 – 60 |
| `alert_timeout_seconds` | 10 – 300 |
| `afk_threshold_minutes` | 1 – 120 |
| `language` | `zh-CN` / `en` |
| `theme` | `light` / `dark` |
| `pomodoro.focus_minutes` | 1 – 180 |
| `pomodoro.short_break_minutes` | 1 – 60 |
| `pomodoro.long_break_minutes` | 1 – 180 |
| `pomodoro.cycles_per_long` | 1 – 12 |

修改范围 MUST 同步更新前端 Stepper 的 `min` / `max`。

### 超时策略

- Command 执行 SHOULD 在 5 秒内完成；前端 `invokeWithTimeout` 已硬编码 5000ms（见 `src/lib/commands.ts`）。
- 涉及磁盘 I/O 的 command（`update_*_config`）MUST 使用 `tokio::task::spawn_blocking` 包裹，避免阻塞 Tauri runtime（实际见 `commands/mod.rs:107`）。
- 前端超时后 MUST 给用户可见反馈（toast / 表单 inline 错误），MUST NOT 静默丢弃。

### 错误返回

- Command MUST 返回 `Result<T, AppError>`。
- Command MUST NOT `unwrap()` 或 `panic!()`；服务内部不可恢复错误 SHOULD 通过 `tracing::error!` 记录并返回 `AppError::IoError`。
- 错误 `reason` MUST 对用户友好，技术细节（stack trace、内部状态）记入日志。

## Timer 状态机

实现在 `src-tauri/src/services/timer/{state.rs,machine.rs,effect.rs,service.rs}`。状态机是**纯函数核心**，副作用通过 `Effect` 在锁外执行。

### 状态

定义见 `src-tauri/src/services/timer/state.rs`：

| 状态 | 含义 | 阶段 |
|------|------|------|
| `Working` | 工作计时中（含 PreAlert 之前）| MVP |
| `PreAlert` | 预提醒：托盘 tooltip 变化 + 可选音效 | MVP |
| `Alerting` | 全屏提醒显示，等待用户操作（超时自动消失）| MVP |
| `Resting` | 用户选择休息，倒计时中 | MVP |
| `Paused` | 用户手动暂停，携带 `paused_from` + `paused_remaining` | MVP |
| `Away` | 离席检测触发 | P2（未实现）|

- `Paused` 数据 MUST 通过 `Inner.paused_from: Option<TimerState>` + `Inner.paused_remaining: Option<Duration>` 承载，MUST NOT 用全局可变状态。
- 恢复时 MUST 通过 `apply_transition` 回到 `paused_from` 并按 `paused_remaining` 重算 `state_entered_at`，MUST NOT 总是跳回 `Working`。
- `TimerState::as_str()` 返回的 `snake_case` MUST 与前端 `StatePayload.state` 字段值保持一致（实际见 `state.rs:21`）。

### 状态转换

```
start --> Working
Working  --tick (elapsed >= work - pre_alert)--> PreAlert
PreAlert --tick (elapsed >= pre_alert)--> Alerting
Alerting --user:start_rest--> Resting
Alerting --user:skip--> Working
Alerting --tick (elapsed >= alert_timeout)--> Working    // 自动消失，计为 skip
Resting  --tick (elapsed >= rest)--> Working
Any(except Paused) --user:pause--> Paused                // 保存 prev_state + remaining
Paused   --user:resume--> prev_state                     // 按 remaining 续跑
Working  --detector:away--> Away                         // P2
Away     --detector:back--> Working                      // P2
```

- 状态转换 MUST 通过 `resolve_user_event()` / `step_time()` 纯函数返回的 `Transition` 触发，MUST NOT 在业务代码中直接 mutate `Inner.state`。
- 非法转换（例如在 `Working` 收到 `Resume`）MUST 返回 `None`，由 `TimerService` 转换为 `AppError::InvalidOperation`，MUST NOT panic。
- `SkipFlags::any_active() == true` 时，`Working` 超时 MUST 重置工作计时器（`Effect::ResetWorkTimer`），MUST NOT 进入 `PreAlert`。
- AFK 跳过当前作为 `SkipFlags::afk_active` 落地，MUST NOT 为该行为引入 `Away` 状态；`Away` 仍保留给未来统计/长离席语义。

### 核心三函数

```rust
// 纯函数：用户事件 → 状态转换
pub(crate) fn resolve_user_event(state: &TimerState, event: UserEvent) -> Option<Transition>;

// 纯函数：时间推进 → 状态转换
pub(crate) fn step_time(inner: &Inner, now: Instant, skip_flags: &SkipFlags) -> Option<Transition>;

// 锁内收集副作用（实际实现：collect_effects + collect_tick_effects）
pub(crate) fn collect_effects(transition: &Transition, inner: &Inner) -> Vec<Effect>;
```

- `resolve_user_event` 与 `step_time` MUST 是纯函数：无 I/O、无 logging、无 `Instant::now()` 之外的副作用。
- `collect_effects` MUST 在持锁状态下调用并立即返回 `Vec<Effect>`；持锁 MUST NOT 跨 `await`。
- 返回的 `Vec<Effect>` MUST 在**锁外**执行，避免回调时反向持锁导致死锁。

### Effect 类型

定义见 `src-tauri/src/services/timer/effect.rs`：

```rust
pub(crate) enum Effect {
    EmitStateChanged(StatePayload),
    ShowTipWindows,
    HideTipWindows,
    PlaySound(SoundType),
    UpdateTray(TrayUpdate),
    ResetWorkTimer(Duration),
}
```

- Effect MUST NOT 持有锁引用或可变 service 引用；通过克隆值传递。
- Effect 执行失败 MUST 记录 `tracing::warn!` 但 MUST NOT 反向抛回状态机，MUST NOT 阻塞下一次 tick。
- `EmitStateChanged` 是前端同步唯一来源；新增状态字段 MUST 同步更新 `StatePayload`（见 `src-tauri/src/models/types.rs`）+ ts-rs 绑定。
- `RecordStat` 等 P2 effect 加入时 MUST 同步更新本表。

### SkipFlags

```rust
pub(crate) struct SkipFlags {
    pub(crate) fullscreen_active: bool,
    pub(crate) schedule_inactive: bool,
    pub(crate) afk_active: bool,
    // P2: whitelisted_process
}
```

- `SkipFlags::any_active() == true` 时，`Working` 超时仅触发 `Effect::ResetWorkTimer(work_duration)`，状态保持 `Working`。
- 添加新 flag MUST 同时扩展 `any_active()`、`step_time` 中的处理，以及对应配置（如 `BehaviorConfig::fullscreen_skip`）。
- `afk_active` MUST 由最新 `BehaviorConfig` + `DetectorService` 同步拉取计算：`afk_skip_enabled && idle_duration >= afk_threshold_minutes`。平台返回 `None` 时 MUST 视为未离席，避免误跳过。
- `afk_active` 抑制提醒时 MUST 记录 `info!("skip: afk")`，但日志 MUST 只在实际 `Working -> Working` skip 转换发生时记录，MUST NOT 每秒 idle tick 刷日志。

### Timer Mode (20-20-20 vs Pomodoro)

`TimerConfig.mode` 决定计时节奏。状态机本身不新增 state — Pomodoro 通过 `Inner` 的 cycle counter 表达长短休。

| 字段 | 类型 | 语义 |
|------|------|------|
| `Inner.mode` | `TimerMode` | `TwentyTwentyTwenty`（默认）/ `Pomodoro` |
| `Inner.cycle_index` | `u32` | 1-based，当前正在进行的 focus session 编号 |
| `Inner.cycles_per_long` | `u32` | 每多少个 focus 安排一次长休 |
| `Inner.short_break_duration` | `Duration` | 短休时长 |
| `Inner.long_break_duration` | `Duration` | 长休时长 |
| `Inner.is_long_break` | `bool` | 当前 Resting 是否为长休 |

规则：

- `apply_transition_at` 在 `* -> Resting`（仅 pomodoro）MUST 根据 `cycle_index.is_multiple_of(cycles_per_long)` 选 short/long break 并写入 `rest_duration` + `is_long_break`。
- `Resting -> Working`（仅 pomodoro）MUST 在 `is_long_break` 时把 `cycle_index` 归回 1，否则 `+= 1`；同时清 `is_long_break`。
- `Working/Alerting -> Working` skip 路径（仅 pomodoro）MUST 清 `is_long_break`，**MUST NOT** 推进 `cycle_index`。
- `Pause/Resume` MUST 完整保留 `cycle_index` 与 `is_long_break`。
- `TimerService::sync_runtime_config` 检测到 `mode` 变化 MUST 重置 `cycle_index = 1` + `state = Working` + `state_entered_at = now`，MUST NOT 保留旧节奏的剩余时间。
- `cycle_index` 不持久化，重启归 1（符合 Pomodoro "session = 单次运行" 的传统）。
- `StatePayload.mode` MUST 总是有值；`StatePayload.pomodoro` MUST 在 20-20-20 模式下为 `null`，在 Pomodoro 模式下为 `Some(PomodoroStatePayload)`。
- Tray tooltip 在 Pomodoro 模式追加 ` (Pomo N/M)` 后缀（两语共用，未走 i18n）。
