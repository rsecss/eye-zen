# 变更管理

> 跨层变更的影响清单、配置兼容、破坏性变更协议、发版流程、依赖管理。
> 关键词约定：**MUST** = 强制，**SHOULD** = 推荐，**MAY** = 可选。

---

## 变更影响清单

每种变更 MUST 完成对应清单的**所有项目**，缺一不可。漏项会被 PR review 阻塞。

### 新增 Tauri Command

- [ ] 在 `src-tauri/src/commands/mod.rs` 定义 `#[tauri::command] pub(crate) async fn`
- [ ] 在 `src-tauri/src/models/` 中定义请求/响应类型（如新增）
- [ ] 类型添加 `#[cfg_attr(test, derive(ts_rs::TS))]` + `ts(export, export_to = "../../src/lib/bindings/")`
- [ ] 在 `src-tauri/src/lib.rs` 的 `tauri::generate_handler![...]` 中注册
- [ ] 新建 `src-tauri/permissions/autogenerated/<command>.toml`
- [ ] 在对应窗口的 `src-tauri/capabilities/*.json` 引用 `allow-<command>` permission
- [ ] 在 `src/lib/commands.ts` 中添加封装（一对一镜像，MUST 用 `invokeWithTimeout`）
- [ ] 运行 `cargo test --manifest-path src-tauri/Cargo.toml` 刷新 ts-rs 绑定并确认前端类型通过
- [ ] 写至少一条边界测试（参数范围 / 错误路径）
- [ ] 校验逻辑遵循 [`ipc-and-state.md`](./ipc-and-state.md#输入校验)（磁盘 I/O 用 `spawn_blocking`）

### 新增 Service

- [ ] 在 `src-tauri/src/services/` 创建模块文件（必要时拆分 `<svc>/mod.rs` + 子文件）
- [ ] 实现 `Service` trait（`init` / `start` / `shutdown`，见 `services/mod.rs`）
- [ ] 添加字段到 `AppServices` struct（`services/mod.rs`）
- [ ] 在 `lib.rs` 的 `setup()` 中按依赖顺序初始化
- [ ] 更新 [`../backend/service-pattern.md`](../backend/service-pattern.md) 的依赖 DAG 与关闭顺序
- [ ] 定义服务间 channel 类型（必要时新建 `models/channels.rs`，pub(crate)）
- [ ] 写单元测试覆盖核心逻辑与状态转换
- [ ] 在 [`../backend/index.md`](../backend/index.md) 服务表中登记

### 新增 Event

- [ ] 在 `src-tauri/src/events/mod.rs` 添加事件名常量
- [ ] 在 `src-tauri/src/models/` 中定义 Payload 类型（带 `#[cfg_attr(test, derive(ts_rs::TS))]`）
- [ ] 运行 `cargo test` 刷新 ts-rs 绑定到 `src/lib/bindings/`
- [ ] 在 `src/lib/events.ts` 添加 `listen<Payload>(...)` 封装
- [ ] 在所有需要监听该 event 的窗口 capability（`src-tauri/capabilities/*.json`）的 `core:event:allow-listen` allow 列表中添加事件名
- [ ] 在 `commands.ts` 调用前先注册 listener，避免初始事件丢失

### 变更 `tauri.conf.json` / 窗口配置

- [ ] 更新 `src-tauri/tauri.conf.json` 中的窗口定义
- [ ] 新增窗口：同步添加 HTML 入口（项目根目录）、`src/entries/<window>.ts`、`src/pages/<window>/`、`vite.config.ts` 的 `rollupOptions.input`

### 变更 Config Schema

- [ ] 更新 [`../backend/platform-storage.md`](../backend/platform-storage.md) 的配置结构说明

### 新增前端页面/组件

- [ ] 组件放置遵循 [`../frontend/directory-structure.md`](../frontend/directory-structure.md)（`pages/<window>/components/` 或 `lib/components/`）
- [ ] 类型从 `$lib/bindings/` 导入，禁止手编 binding
- [ ] Props 使用 `$props()` + callback 模式，MUST NOT 使用 `bind:` 让外部直接写内部状态
- [ ] 单文件超过 200 行 SHOULD 按职责评估拆分
- [ ] 可复用组件 MUST 写 Vitest（渲染 + props 响应 + 交互回调 + 边界值），详见 [`testing-quality.md`](./testing-quality.md#变更类型与测试要求)
- [ ] 页面组件 SHOULD 写关键交互路径测试
- [ ] CSS 颜色 MUST 使用 `src/app.css` 中的 CSS 变量，MUST NOT 硬编码色值（影响主题切换）
- [ ] `npm run build` + `svelte-check` + `npm test -- --run` 三项全过

## 配置向后兼容

### 规则

- 新增字段 MUST 提供 `#[serde(default = "...")]`，旧 TOML 文件 MUST 能正常加载（实际覆盖：`models/config.rs::partial_toml_uses_defaults` / `empty_toml_uses_all_defaults`）。
- 重命名字段 MUST NOT 直接操作：先新增 → 双写迁移 → 下一版本移除旧字段（跨两个版本）。
- 删除字段 MUST 在 `CHANGELOG.md` 中标注，并保留至少一个版本的 deprecation 期。
- 配置解析失败 MUST 保留 `.bak` 备份再启用默认值，MUST NOT 静默覆盖；详细实现要求见 [`../backend/platform-storage.md`](../backend/platform-storage.md)。

### 迁移策略

```rust
fn migrate_if_needed(config: &mut Config) {
    // 新增字段：缺失时 serde default 已覆盖
    // 类型变更：尝试转换，失败则回退默认值 + tracing::warn 日志
}
```

- MAY 在 `Config` struct 中加 `config_version: u32` 用于未来迁移；当前 MVP 简单处理足够。
- 字段语义变更（含义改了但名字没变）MUST 走破坏性变更协议。

## 破坏性变更协议

### 什么构成破坏性变更

- 改变 IPC Command 的参数类型 / 返回类型 / 名称
- 改变 Event Payload 的字段结构（含改名、删字段、改类型）
- 移除 / 重命名 Config 字段（语义改变也算）
- 改变状态机的转换规则（已有 `start_rest` 行为变化等）
- 改变 `AppError` variant（前端按 `kind` 分支）
- 改变服务间 channel 的消息类型（影响多服务编排）

### 处理流程

1. Commit 消息 MUST 使用 `!` 标记：`feat(api)!: redesign config update commands`
2. Commit body MUST 包含 `BREAKING CHANGE:` 段落，说明影响与迁移方法
3. 同 PR MUST 同时改前端（消费侧）+ 后端（实现侧）+ permission/capability，MUST NOT 留半截兼容期
4. MUST 更新对应 spec：[`ipc-and-state.md`](./ipc-and-state.md)（命令/事件/状态机契约）、相关 backend / frontend spec
5. SHOULD 在 PR 描述里列出 risk surface 与回滚策略

## 发版清单

发版 MUST 按顺序完成，MUST NOT 跳步。完整步骤详见 [`../../../docs/workflows/release.md`](../../../docs/workflows/release.md)。

### 1. 本地全量验证（在 `dev` 分支）

```bash
npm run ci
```

`npm run ci` 全部通过才可推送 dev。等价于 `.husky/pre-push` 检查（见 [`testing-quality.md`](./testing-quality.md#pre-pushhusky)）。

### 2. 推送 dev 并等待 CI 绿灯

```bash
git push origin dev
```

- 等待 `.github/workflows/ci.yml` 三平台（Windows / macOS / Linux）parity checks + audit job 全部通过。
- MUST NOT 在 CI 未通过时合并到 main。

### 3. 通过 PR 合并到 main

- MUST 走 PR 工作流（[`../../../docs/workflows/pr.md`](../../../docs/workflows/pr.md)），MUST NOT 直接 `git merge dev main` 推送
- PR 描述 MUST 包含版本号 + 变更摘要 + 已知风险
- 推荐 squash merge，保持 main 历史干净
- v0.1.0 的教训：曾经直接合并到 main 触发了一连串 CI 修复（见 `memory/release-v010-experience.md`），MUST 严守 PR 流程

### 4. 版本号三处同步

| 文件 | 字段 |
|------|------|
| `package.json` | `"version"` |
| `src-tauri/Cargo.toml` | `[package].version` |
| `src-tauri/tauri.conf.json` | `"version"` |

额外手动更新：`README*.md` badge、`src/pages/about/` 版本号。

### 5. Tag 与 Release

```bash
git checkout main && git pull origin main
git tag v<VERSION>
git push origin v<VERSION>
```

- Tag MUST 在 main 上创建，MUST NOT 在 dev 上创建。
- 推送 tag 后 `.github/workflows/release.yml` 自动跑四目标 Tauri 打包（Win / Linux / macOS ARM / macOS Intel）+ Windows portable zip。普通 push / PR CI MUST NOT run packaging by default.

### 6. 验证 Release 制品

- 等待 release workflow 四目标全部完成
- 检查 Draft Release 中制品命名遵循 [`../../../docs/workflows/release-naming.md`](../../../docs/workflows/release-naming.md)
- 手动 Publish Draft Release

### 第三方 Action 版本管理

- `tauri-apps/tauri-action` MUST 使用 `@v0`（v1 tag 已被上游删除，强行 pin 到 v1 会 fetch 失败）
- 关键 Action SHOULD 考虑 pin 到具体 commit SHA（dependabot 触发后审核更新）
- Rust and Node versions MUST be pinned in `rust-toolchain.toml` and `.nvmrc`; GitHub Actions MUST read those files instead of floating `stable` / `lts/*` aliases.
- `swatinem/rust-cache@v2`、`actions/setup-node@v4` 是当前基线，升级 MUST 单独 PR 验证

## 依赖管理

### 引入新依赖前 MUST 评估

| 维度 | 要求 |
|------|------|
| 必要性 | 标准库或现有依赖能否解决？ |
| 维护状态 | 近 6 个月有更新？star / issue 活跃度？ |
| 体积影响 | 对 bundle size / 编译时间 / Tauri 制品体积 |
| 许可证 | MIT / Apache-2.0 / BSD（拒绝 GPL / AGPL / 未声明） |
| 替代方案 | 至少考虑一个替代方案并说明选择理由 |

### 版本策略

- npm 与 Cargo 依赖 MUST 使用 tilde 锁定（`~x.y.z`）；当前 `package.json` 与 `src-tauri/Cargo.toml` 已全量遵循。
- MUST NOT 使用 `*` 或 `>=` 版本范围；MUST NOT 使用 caret（`^`）。
- 依赖更新 MUST 单独提交（`chore(deps): bump <name> from x to y`），不与功能代码混合。
- 新增 Cargo 依赖 MUST 同时跑 `cargo audit --file src-tauri/Cargo.lock`，CI 已强制（`.github/workflows/ci.yml` audit job）。
- ts-rs 升级可能改变绑定文件格式（分号 / 逗号 / 换行），MUST 跑 `cargo test` 重新生成并提交，详见 [`testing-quality.md`](./testing-quality.md)。
